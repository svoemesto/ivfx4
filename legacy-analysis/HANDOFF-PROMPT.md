## Текст задачи

Создай новый проект с нуля: **веб-приложение для кинематографического анализа
видеоархива**. Функциональность переносится со старого проекта `ivfx4` (2021–2022,
десктопное JavaFX-приложение, закрыт в 2022 году).

### Что делает продукт

Инструмент кинематографического анализа видеоархива: разложить видеофайлы на кадры,
автоматически найти границы **планов (шотов)** и **сцен**, детектировать и **распознать
лица** (привязать к персонам), дать оператору интерфейс для **ручной доводки** результата
и уметь **собрать экспортную выборку** (например, все планы с актрисой X по всем сценам)
в один видеофайл. Подробное описание — в `00-OVERVIEW.md`.

### Стек — строго как в Karaoke

Эталон — проект `/home/nsa/Karaoke`. Изучи его до начала проектирования:
`AGENTS.md`, `.specify/memory/constitution.md`, `knowledge/README.md`,
`knowledge/guidelines/architecture-conventions.md`, `deploy/`.

- Gradle multi-module, Kotlin 2.2, Spring Boot 3.5.6, JDK 17
- **PostgreSQL 16** + нумерованные SQL-миграции в `deploy/<имя>-db/NN_*.sql`
- **Сырой JDBC**, персистентность по образцу `KaraokeDbTable`
- **Vue 3 + Vite + Bootstrap 5** во фронтенде, сборка через `node:22-alpine` → `nginx:stable`
- Всё в **docker-compose**, сборка/деплой через скрипт в стиле `deploy/do.sh`
- Асинхронные операции — через очередь заданий по образцу `KaraokeProcessWorker`
  (статусы `CREATING/WAITING/WORKING/DONE/ERROR`, прогресс из stdout, forceStop)

### Жёсткие запреты

- **Никакого JPA/Hibernate** — это прямой запрет конституции Karaoke, проверяется guard'ом
- Рендеринг видео — через **melt/MLT**, не через прямой ffmpeg (вспомогательные операции
  вроде нарезки и probe — можно)
- Секреты — только через переменные окружения, ничего в git
- Публичные API — с KDoc 100 % и ссылкой на документ фичи
- Линтеры ktlint и ESLint должны проходить

### Что переносим, а что переписываем

**Переносим как есть (ценные находки):** трёхуровневую модель фильтров
`Filter → FilterGroup → FilterCondition`; матрицу кадров, где граница плана разрывает
строку; цветовую семантику оверлеев (красный = алгоритм, зелёный = оператор, оранжевый =
отмена); мастер-копию lossless как единственный источник нарезок; ручную доводку
(split/union плана двойным кликом, рисование лица мышью, drag&drop лица на персону).

**Переписываем:** персистентность (JPA → JDBC), сетевой слой (его не было вообще),
очередь и отмену операций, работу с внешними бинарями (в старом проекте `ffmpeg.exe`
лежал внутри JAR под Windows), Python-транспорт (был запуск `.cmd`).

Полный список — в `README.md`, раздел «Что взять как есть / что переписывать».

### Что нужно сделать по процессу

1. Прочитай отчёты и при необходимости исходники старого проекта.
2. Сформулируй **карту решений** (что переносим, что упрощаем, что выкидываем,
   чем это грозит) и **задай владельцу уточняющие вопросы** — они есть в
   `legacy-analysis/README.md`, раздел «Открытые вопросы к владельцу» (7 пунктов).
   Не начинай проектирование, пока эти ответы не получены: от них зависит,
   однопользовательское это приложение или веб-сервис, где живёт видеоархив
   (диск или MinIO) и нужен ли массовый прогон каталогов.
3. После ответов владельца — спецификация, план, задачи, реализация.
4. По ходу работы веди документацию в том же духе, что в Karaoke: `knowledge/`
   с картой доменов, ADR на ключевые решения, per-feature документы.

### Осторожно

- В старом проекте **не было HTTP API** — «контроллеры» были обычными Kotlin-объектами,
  вызываемыми из UI в том же процессе. Не ищи там примеров REST и не переноси
  архитектуру «вызовов напрямую».
- `@Transactional` в старом проекте **не работал** на UI-классах (их создавали вручную,
  минуя Spring-контейнер). Не бери это как образец.
- Схема `*Cdf` (per-machine пути, `Main.ccid` через OSHI) существовала из-за «общая БД,
  разные машины». Если в новом проекте один хост — **убери её**, не переноси.
- В старом коде много ловушек: баг bramp 0.6.2 (`setVideoFilter()` эмитит `-af`),
  мёртвая ветка `diffPrev2`, хардкод `_lossless.mkv`, парсинг ffprobe с `\r\n`.
  Полный список дефектов — в отчётах, **не переноси их**.
