## Context & Problem | Контекст и проблема

Приложение достаёт свои ресурсы по файловому пути из `getResource()`: картинки
заглушек, скрипты детекции лиц, пиктограммы типов плана, утилиты. Путь
используется как настоящий файловый путь — его передают в `ProcessBuilder`
или подставляют в команду.

При запуске из банка так не работает: `getResource()` отдаёт не путь, а URI
вида `jar:file:/...app.jar!/com/...`, у которого `getPath()` возвращает
`null`, и загрузка класса падает с NPE. По той же причине не работает и
`getResource().path` — он даёт строку `file:/...jar!/...`, которую
`ProcessBuilder` принять не может.

## Decision | Решение

Приложение запускается **из каталога `target/classes`**, а не из собранного
банка. Банк при этом собирается (`mvn package`) и существует, но для запуска
не используется.

```bash
bash run-old-app.sh        # единственная поддерживаемая точка запуска
```

Скрипт собирает классы, готовит classpath, кладёт банки с нативными
библиотеками JavaFX в **модульный путь** (`--module-path`, `--add-modules`),
а остальное — в classpath, и запускает `com.svoemesto.ivfx.apps.ProjectFXApp`
против `target/classes`.

## Rationale | Обоснование

Это режим, в котором проект писался и в котором он проверен: автор запускал
приложение из IDE, а не из банка. Формально сборка банка работоспособна,
но запуск из него не проверялся и, по устройству кода, неработоспособен.

Отдельно: JavaFX 11 не запускается с classpath — нужны банки с нативными
библиотеками в модульном пути, иначе «JavaFX runtime components are missing».

## Consequences | Последствия

**Отрицательные**

- Собранный `.jar` не является точкой входа. Кто-то может решить, что раз
  банк собирается, то и запускается, и упасть с NPE внутри загрузки ресурса.
- Нет поставки: приложение не разворачивается как отдельный артефакт.
- Любой новый код, читающий ресурс по пути, обязан учитывать это ограничение.

**Положительные**

- Поведение совпадает с режимом разработки: то, что проверяют, то и работает.

**Что делать при изменении**

- Новые ресурсы, к которым идёт обращение по пути, должны работать из каталога.
- `getResource(...).path` в `ProcessBuilder` передавать нельзя никогда.
- Настоящее решение — перевести чтение ресурсов на `getResource().toURI()`
  или извлечение во временный каталог; тогда запуск из банка станет возможен.
  Это отдельная задача, здесь она зафиксирована как долг.
