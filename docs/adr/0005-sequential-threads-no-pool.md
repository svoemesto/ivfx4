## Context & Problem | Контекст и проблема

16 долгих операций обработки видео (`threads/projectactions/`) запускаются из
одного окна. Каждая — отдельный поток. Запускает их `RunListThreads`:
он берёт список потоков и проходит его **строго последовательно**, опрашивая
`isAlive` с паузой `sleep(100)`.

Пул потоков в проекте отсутствует полностью: `ExecutorService` и `Executors`
не встречаются ни разу.

## Decision | Решение

Обработка выполняется последовательно, по одной операции за раз. Это
осознанно: операции одного файла зависят друг от друга (`Create lossless` →
`Create frames` → `Analyze frames` → `Create shots` → детекция лиц), и
параллельный запуск дал бы гонки за промежуточными файлами.

Прогресс двухуровневый: `pb1` считает общий проход по списку операций, `pb2` —
процент внутри текущей операции. Оба обновляются через `Platform.runLater`.

## Rationale | Обоснование

Выигрыш от параллелизма перекрывается сложностью синхронизации артефактов на
диске. Последовательность гарантирует, что каждая следующая операция видит
результат предыдущей.

## Consequences | Последствия

**Отмена не работает.** Это главное следствие.

- `projectactions` **не проверяют** `isInterrupted` в циклах и **не убивают**
  дочерние процессы ffmpeg. Прерванная операция продолжает работать.
- `RunListThreads` при прерывании не выставляет `flagIsDone`, поэтому интерфейс
  зависает на полосе прогресса до конца операции.
- `CreateFilterResult(...).run()` вызывается на FX-потоке и **блокирует
  интерфейс**.

**Процессы переживают приложение.** При завершении JVM дочерние
`multiprocessing`-воркеры Python не наследуют завершение родителя: найдены
процессы, простоявшие 42 часа.

**Закрытие окна не завершает JVM.** `Platform.exit()` и `System.exit(0)`
по закрытию главного окна не вызываются. Проверено 2026-10-07: после закрытия
окна процесс держал **24,2 ГБ RAM (208% физической памяти)**, пока его не
убили вручную. Следствие — следующий запуск падал с
`IllegalStateException: The file is locked` на `h2db.mv.db`.

**Что делать при изменении**

- Пул потоков вводить **только** вместе с защитой от гонок за артефакты.
  «Просто завернуть в `ExecutorService`» сломает зависимости между операциями.
- Операция обязана проверять `isInterrupted` в цикле и убивать свой
  дочерний процесс.
- После закрытия приложения проверять, что процесс действительно умер.
