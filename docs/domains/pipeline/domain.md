# Домен: Пайплайн обработки

## Обзор контекста (Bounded Context)

Долгие операции над файлом: извлечение кадров, анализ, поиск планов,
детекция и распознавание лиц, нарезка и склейка. Запускаются все с одного
экрана и выполняются последовательно.

## Dependencies | Зависимости

- `media-file`, `frames`, `shots`, `faces` — операции пишут результат в эти домены
- ADR-0005 — последовательные потоки, отмена не работает
- ADR-0003 — детекция лиц требует кешированных моделей

## Ubiquitous Language | Единый язык

- **Операция**: одна долгая обработка одного или нескольких файлов
- **Индикатор выполнения**: булево свойство «артефакт существует»
- **Пересоздать**: флаг, разрешающий выполнить операцию повторно

## Публичные контракты (API)

### Internal API (для других модулей системы)

`threads/projectactions/` — 16 классов-операций;
`threads/RunCmd.kt` — запуск внешних программ;
`threads/RunListThreads.kt` — последовательный оркестратор.

## Domain Invariants | Инварианты и правила бизнеса

- Операция выполняется, если её индикатор сброшен **или** включён флаг
  «пересоздать». Это единственная идемпотентность в системе.
- Порядок операций жёсткий: превью → мастер-копия → кадры → анализ →
  планы → лица → распознавание → нарезка → склейка.
- Предусловия («нужна мастер-копия», «нужны нарезки без звука») проверяются
  **только человеком** по надписям, программной проверки нет.
- Возвращаемые коды внешних процессов игнорируются: сбой Python не виден
  в интерфейсе.

## Структура компонентов (C4 L3)

- `threads/projectactions/` — 18 операций
- `threads/RunListThreads.kt`, `threads/RunCmd.kt`
- `utils/IvfxFFmpegUtils.kt`, `utils/MediaInfo.kt`
- `fxcontrollers/ProjectActionsFXController.kt` — запуск и прогресс
