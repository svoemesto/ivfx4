# Домен: Фильтры

## Обзор контекста (Bounded Context)

Трёхуровневая система отбора планов. Это главный инструмент работы оператора:
выбрать все планы с определённой персоной, на определённом типе плана, с
определённым свойством — и получить готовую выборку.

## Dependencies | Зависимости

- `shots` — объект отбора — планы
- `faces`, `properties` — используются в условиях
- ADR-0005 — свёртка выборок идёт в памяти, ограничение по числу элементов

## Ubiquitous Language | Единый язык

- **Фильтр**: верхний уровень, своё имя
- **Группа**: средний уровень внутри фильтра
- **Условие**: нижний уровень, единственное правило отбора
- **И/ИЛИ**: своё поведение у каждого уровня: истина — все условия,
  ложь — хотя бы одно

## Публичные контракты (API)

### Internal API (для других модулей системы)

`controllers/FilterController`, `FilterGroupController`, `FilterConditionController`;
`modelsext/FilterExt`, `FilterGroupExt`, `FilterConditionExt`.

## Domain Invariants | Инварианты и правила бизнеса

- Свёртка выполняется **в памяти**: истина — пересечение множеств,
  ложь — объединение.
- Поддерживаются пять типов условий: «персона», «свойство персоны»,
  «свойство плана», «свойство сцены», «свойство события».
- Область отбора задаётся заранее: выбранные файлы раскладываются во временную
  таблицу, и условия применяются внутри неё.
- Свойства берутся из **общей** таблицы свойств, а не из per-machine.
- **Пустая выборка — пустая, а не «вся».** И «И», и «ИЛИ» без условий дают
  пустое множество. Это противоположно математике, где «И» по пустому
  семейству истинно; здесь оно означает «ничего не выбрано», и замена на
  пустое истинное значение молча изменила бы результат фильтра.

## Структура компонентов (C4 L3)

- `models/Filter.kt`, `models/FilterGroup.kt`, `models/FilterCondition.kt`
- `controllers/Filter*Controller.kt`
- `repos/ShotRepo.kt` — нативные запросы, по одному на тип условия
