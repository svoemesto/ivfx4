# Сборка и запуск

## Инструменты

```bash
MVN=~/.local/opt/apache-maven-3.9.16/bin/mvn   # в PATH maven нет
JAVA_HOME=/usr/lib/jvm/jdk-18                  # JDK 18.0.2.1
```

## Сборка

```bash
$MVN -q compile             # компиляция
$MVN -q clean compile       # полная пересборка — только при остановленном приложении
$MVN -q package             # банк собирается, но для запуска не нужен
```

Проект собирается под Java 8 (`source/target 8`) на JDK 18 — это
предупреждение, а не ошибка.

**`clean` — только при остановленном приложении.** Формы читаются с диска при
каждом открытии окна, а `clean` их удаляет; окно после этого падает с «Location
is not set».

**Проверку встроили в сборку.** Правило было нарушено дважды за один день
одинаковым способом: команда проверки PID стояла в той же строке, что и
сборка, и её вывод просто не смотрели. Поэтому есть скрипт:

```bash
bash tools/build.sh              # clean + тесты; откажется, если приложение живо
bash tools/build.sh --no-clean   # собрать при живом приложении
```

Код возврата при живом приложении — **1**, сборка не тронута. Проверено на
работающем приложении.

Проверка вручную по-прежнему верна, но нужна редко:

```bash
ps -eo pid,args --no-headers | awk '/ProjectFXApp/ && /java/ && !/awk/ {print $1}'
# пусто — можно; не пусто — сначала остановить, потом собирать
```

## Запуск

```bash
bash run-old-app.sh
```

Только из `target/classes` — см. ADR-0004. Банк запускать нельзя.

## Модели лиц

```bash
bash tools/fetch-models.sh     # скачать при первом запуске, ~275 МБ
```

Без моделей приложение работает, кроме распознавания лиц.

## Индексы в базе

```bash
PGPASSWORD=… psql -d ivfx -f tools/add-indexes.sql    # идемпотентно
```

Hibernate внешние ключи объявляет, но индексы под них не создаёт, и в базе их
нет. Скрипт ставит их один раз при развёртывании.

## Проверки

```bash
python3 docs/scripts/lint-docs.py     # структура документации
bash tools/check-fx-wiring.sh         # связь FXML и контроллера + сборка
bash tools/check-ktlint.sh             # стиль Kotlin, отпечаток состояния
~/.local/opt/apache-maven-3.9.16/bin/mvn -B test   # 28 тестов
```

Перед коммитом прогоняются все четыре.

## После закрытия приложения

Проверять, что процесс умер: `ps -ef | grep com.svoemesto.ivfx`.
Закрытие главного окна завершает JVM (исправлено 2026-10-07, задача #230) —
см. ADR-0005.

**RSS процесса после закрытия остаётся высоким** — это куча JVM, которая не
возвращается системе, а не живые объекты. Мерить память надо `jmap -histo:live`.

## Гигиена git

`.gitignore` обязателен, но **для уже отслеживаемых файлов он не действует**:
нужен `git rm --cached`. Тяжёлые артефакты — модели лиц, полные дампы базы —
в репозитории не хранятся. Проверено 2026-10-08: `git add -A` втянул в коммит
1,3 ГБ дампов; `.gitignore` на неотслеживаемом файле это предотвращает, на уже
отслеживаемом — нет.
