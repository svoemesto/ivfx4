# #243 — Лица персоны выводятся вразнобой

Дата: 2026-10-08. Статус: на проверке владельцу.

## Жалоба

Владелец: «Когда в Persons выбираешь какого-то персонажа, его лица показываются
вразнобой. Но если из лиц какое-то лицо задать другому персонажу, то оставшиеся
лица "перерисовываются" и группируются по трекам, в том порядке, в котором они
идут от плана к плану в файле — так и должно быть сразу при выборе персонажа».

Симптом описывает не поломку сортировки, а **отсутствие сортировки**: правильный
порядок появлялся только как побочный эффект чужого действия.

## Причина

**В `FaceRepo` нет ни одного `ORDER BY`** — проверено:

```bash
grep -n "order by\|ORDER BY" src/main/kotlin/com/svoemesto/ivfx/repos/FaceRepo.kt
# пусто
```

Postgres отдаёт строки в порядке размещения на диске. Загрузчик
`LoadListPersonFacesExtForFile` добавлял их в список в порядке выдачи запроса,
а раскладка матрицы (`MatrixPageFaces.createPages(listFacesExt, …)`) этот порядок
сохраняла.

Проверено на живой базе — самый частый персонаж E03:

| | первые кадры |
|---|---|
| как отдаёт БД | `50618, 1129, 67421, 50618, 53627, 67431, 78544…` |
| после сортировки | `1129, 36866, 36886, 36906, 36926…` |

Почему порядок «появлялся» после переназначения: `reorganizeMatrixFaces()`
собирает новый список из уже отрисованных страниц и **сортирует его** через
`Face.compareTo`. То есть правильный порядок в проекте был, но только на одном
из двух путей, ведущих к одному и тому же списку.

## Что сделано

`list.sort()` в конце трёх загрузчиков лиц — `LoadListPersonFacesExtForFile`,
`LoadListPersonFacesExtForAll`, `LoadListPersonFacesExtForShot`. Компаратор
`FaceExt` → `Face.compareTo` уже существовал и даёт ровно нужный порядок:
файл по `file.order`, затем кадр, затем номер лица в кадре.

**Почему не в SQL.** Порядок по файлам — это `file.order` из `tbl_files`, а не
колонка `tbl_faces`. Чтобы выразить это в запросе, понадобился бы `JOIN` с
`tbl_files` в каждом из трёх запросов, и компаратор всё равно остался бы в
Java. Загрузчик — короче и использует уже написанное сравнение.

## Проверка

| Проверка | Результат |
|---|---|
| `grep "ORDER BY" FaceRepo.kt` | пусто — ни одного `ORDER BY` |
| Порядок выдачи на живой базе | `50618, 1129, 67421…` — не отсортирован |
| `grep "list.sort()" LoadListPersonFacesExt*.kt` | 3 из 3 |
| `mvn -B test` | 28 тестов, 0 падений |
| `bash tools/check-fx-wiring.sh` | форма связана, сборка проходит |
| `bash tools/check-ktlint.sh` | новых нарушений нет |
| `python3 docs/scripts/lint-docs.py` | 0 |
| Новый запуск приложения | PID 2528260, 0 ошибок в журнале |

**Чего не проверено машинно:** порядок на экране. Проверка владельца: выбрать
персону во вкладке Persons — лица должны идти подряд, по кадрам, группами по
трекам, с первой страницы. Можно сравнить с тем, что получалось раньше после
переназначения одного лица: результат должен совпасть.

## Что осталось

- `doSelectFacesRb` — переключатель лиц по-прежнему только пишет в журнал.
- `doSelectFacesCb` разыменовывает `currentPersonExt!!`: щелчок по любому из
  четырёх флажков до выбора персоны уронит поток загрузки. Отдельная правка.
