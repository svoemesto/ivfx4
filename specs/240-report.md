Одно открытие окна редактирования планов стоит около **6 ГБ**, три открытия подряд — 17 ГБ, затем `OutOfMemoryError: Java heap space`.

Освобождение памяти **было написано** в `clearOnExit`, но не выполнялось. Причин две:

1. В проекте стояли два `mainStage.setOnCloseRequest`, и второй перезаписывал первый — обработчик с очисткой был мёртвым кодом.
2. Главная причина: **`Stage.close()` не порождает событие закрытия.** Обработчик `onCloseRequest` срабатывает только по крестику или системному закрытию окна, а кнопка «ОК» вызывает `close()` напрямую и обработчик не задействует. Оператор закрывал окно кнопкой — очистка не выполнялась **никогда**.

## Исправление

`clearOnExit()` вызывается явно из `doOK` плюс остаётся в обработчике для крестика; пути не пересекаются. Заодно убрано обращение `currentFileExt!!`, падавшее бы с `NullPointerException` при закрытии с пустым файлом.

## Побочно

Гипотеза, что причиной был `enable_lazy_load_no_trans`, **не подтвердилась** — живых сущностей `Frame` осталось 0,03 ГБ. Гипотеза убрана из правил.

В правила внесено предупреждение: RSS после освобождения остаётся высоким (9,5 ГБ), потому что куча JVM не возвращается системе; мерить надо `jmap -histo:live`, а не по `VmRSS`.
