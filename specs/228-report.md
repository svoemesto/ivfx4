# Отчёт: живые доки — карта, домены, ADR

Задача #228. Шаг 2 плана «привести проект к рабочему состоянию».

## Что сделано

Каркас SSoT развёрнут через `bootstrap-living-docs`, `docs/` наполнена
по факту существующего кода. 25 документов:

| Раздел | Содержимое |
|---|---|
| `docs/README.md` | карта системы, карта кода, порядок работы для агентов |
| `docs/system/` | L1 — кто пользователь и что на входе/выходе; L2 — контейнеры, иерархия папок, база, внешние процессы |
| `docs/domains/` | 9 доменов: проект, видеофайл, кадры, планы, сцены и события, лица и персоны, фильтры, свойства, пайплайн |
| `docs/adr/` | 5 решений, принятых неявно |
| `docs/guidelines/` | сборка и запуск; восемь ловушек |
| `docs/howto/` | рецепты для оператора и для разработчика |
| `docs/scripts/lint-docs.py` | линтер документации |

ADR: ручной Spring-контекст; per-machine пути через `*Cdf`; модели лиц не
в git; запуск только из `target/classes`; последовательные потоки.

Домены описывают **инварианты**, а не перечисляют классы. Например:
принадлежность плана к сцене вычисляется сравнением диапазонов кадров и в базе
не хранится; ошибочно признанное лицо опаснее непризнанного, потому что оно
попадает в базу и само становится образцом при следующем прогоне.

## Решение по CLAUDE.md

Фрагмент бутстрапа требует идентичности `CLAUDE.md` и `AGENTS.md`.
`CLAUDE.md` в ivfx4 **не создан намеренно**: единственный источник правил —
`AGENTS.md`, который читает DSH. Вторая копия разъехалась бы с первой при
первом же расхождении. Решение записано в правила явно.

## Что проверено и как

| Проверка | Результат |
|---|---|
| `python3 docs/scripts/lint-docs.py` | All documentation passes architectural style and structural checks |
