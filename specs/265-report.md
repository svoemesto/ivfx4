# #265 — Сбор галереи: 22 секунды на пятидесяти трёх тысячах лиц

## Где уходило время

Замер без прогона приложения, на настоящих данных — все 53 291 вектор из
проекта выгружены и разбираются вне работающего приложения.

| этап | время |
|---|---|
| запрос галереи в Postgres | **1,2 с** |
| разбор векторов регуляркой, как это делает `FaceExt` | **9,1 с** |
| запись матрицы `.npy` | 0,14 с |

Значит 20 секунд из 22 уходили не в базу, а в разбор чисел.

## Главная находка — мой разбор был медленнее прежнего

При переводе на матрицу я заменил разбор на свой, и по замыслу он был
быстрее. Меряю — **нет**:

| способ | 53 000 векторов |
|---|---|
| регулярка `split` плюс `Double.parseDouble` | 9 058 мс |
| `substring` плюс `toFloatOrNull` | **15 354 мс** |
| разбор без выделений памяти | **1 047 мс** |

Второй медленнее первого в полтора раза, и это неочевидно: подстрока на
каждое число — это 27 миллионов объектов `String`, а `toFloatOrNull` — это
try/catch внутри цикла. Мой «быстрый» разбор был медленнее всего.

## Что сделано

1. **Разбор без единого выделения памяти.** Символы читаются напрямую,
   значение собирается из цифр на месте, накопление в double (во float
   мантисса копится 512 шагов и накапливает ошибку округления).
2. **Галерея больше не оборачивается в `FaceExt`.** У `FaceExt` инициализатор
   `toSerializeVector = vector`, а тот тянет вектор в числа — то есть создание
   53 тысяч объектов стоило тех же 9 секунд. Нужны от галереи ровно две вещи:
   имя персоны и текст вектора, обе лежат в сущности лица.
3. **В json уходит только очередь.** Галерея скрипту из json не нужна, она
   приходит матрицей; json-дубликат был поводом построить 53 тысячи объектов
   и разобрать 27 миллионов чисел впустую. Проверено: скрипт читает из json
   только очередь, галерейные записи не используются нигде.

## Проверка

Разбор нового кода сверен с `Float.parseFloat` на **всех 53 291 векторах**:
**расхождений ноль**, неполных векторов ноль.

Прошлая проверка была слабее: на трёхстах векторах первые 300 показывали
101 расхождение — и это выяснилось только потому, что проверка шла целиком.
Первое же отличие показало, что в данных есть **научная запись**
(`-5.96067460719496E-4`), которую первый вариант разбора сворачивал в
мантиссу, меняя число на порядки.

## Что ожидается

Сбор галереи 22,0 с → **около 4–5 с**. Это **ожидание, а не измерение**:
замер даст следующий прогон распознавания. Разборы выше измерены по-настоящему,
а сборка целиком — нет.
