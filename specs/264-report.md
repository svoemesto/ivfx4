# #264 — У лица появилась связь с кадром

## Что было

Лицо знало только серию и номер кадра, то есть принадлежность кадру была
**выводимой**, а не записанной. Этого хватало ровно до аварии 2026-10-08:
перезапуск создания лиц переписал серию у 45 136 лиц, и в базе не осталось
ничего, по чему исходную серию можно было бы узнать — у `tbl_faces` серия
записывалась отдельно, а у `tbl_faces_tracks` её нет вовсе.

## Что сделано

| | |
|---|---|
| колонка | `tbl_faces.frame_id bigint` |
| индекс | `idx_faces_frame` |
| внешний ключ | `fk_faces_frame` → `tbl_frames(id)` |
| скрипт | `tools/add-face-frame-link.sql`, **идемпотентный** |
| сущность | поле `Face.frame`, ленивое |

Заполнение идёт по имеющимся данным: кадр ищется по паре «серия + номер
кадра». Скрипт **проверяет себя**: если после заполнения осталось хоть одно
лицо без кадра, он бросает исключение и откатывает всё.

## Проверка на живых данных

```
 лиц  | со_связью_на_кадр | серия_совпадает | серия_расходится
 80508 |            80508 |           80508 |                0
```

**80 508 лиц из 80 508**, и ни одного расхождения между серией лица и серией
его кадра. То есть заполнение не придумало связей: там, где кадр нашёлся,
он оказался тем самым.

## Код поддерживает ссылку

При пакетном применении лица кадры файла читаются **одним запросом** и
раскладываются в карту по номеру; ссылка проставляется и новому лицу, и
существующему без неё.

Почему и для существующего тоже: иначе ссылка накапливалась бы только у
новых лиц, а у старых осталась бы пустой — то есть ровно на тех, где она
нужна для разбора.

## Что это даёт

Серия у лица и серия у кадра стали **двумя независимыми записями**. Если
серия снова окажется затёрта, исходная определяется по кадру всегда:

```sql
SELECT fl.order_file FROM tbl_faces f
  JOIN tbl_frames fr ON fr.id = f.frame_id
  JOIN tbl_files fl ON fl.id = fr.file_id
 WHERE f.file_id <> fl.id;   -- расхождения видны сразу
```

Именно этого запроса сегодня не существовало.

владельца. Схема уже изменена на живой базе — колонка добавлена и заполнена,
приложение её не использует до пересборки, но и не мешает.

Проверка после перезапуска: прогнать создание лиц на седьмой серии и
убедиться, что новые лица получают ссылку.
