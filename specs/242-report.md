# #242 — Переключатель «All / File» у персон

Дата: 2026-10-08. Статус: на проверке владельцу.

## Жалоба

Владелец прислал три скриншота редактора планов (E03):

1. Выбрано **File** — список персон серии на месте, персоны плана на месте.
2. Переключение на **All** — список персон на вкладке «Persons» **пуст**.
3. Переключение обратно на **File** — персоны вернулись, но **пропали персоны
   плана** (узкий список в середине окна).

## Причина

Обработчик `doSelectPersonsRb` был не пустым — он переключал **видимость двух
разных таблиц**:

```kotlin
if (all) {
    tblPersonsAllForShot?.isVisible = true
    tblPersonsAllForFile?.isVisible = false
} else {
    tblPersonsAllForShot?.isVisible = false
    tblPersonsAllForFile?.isVisible = true
}
```

Таблицы стоят в **разных местах окна** (`shots-edit-view.fxml`):

| Таблица | Где | Что в ней |
|---|---|---|
| `tblPersonsAllForShot` | середина окна, рядом с переключателями | персоны **выбранного плана** |
| `tblPersonsAllForFile` | правая панель, вкладка «Persons» | персоны **серии** |

Отсюда ровно наблюдаемое: на «All» скрывался список серии, на «File» — список
плана. Данные не терялись, элементы управления просто скрывались.

Ошибка в том, что смысл переключателя был выведен из формы («две кнопки — две
таблицы»), а не из задачи оператора. Соседний переключатель лиц
`doSelectFacesCb` в двадцати строках выше уже делал правильно: различал
`rbFaceFile` и `rbFaceAll` и выбирал **загрузчик данных**.

## Что сделано

1. **`doSelectPersonsRb`** больше не трогает видимость таблиц. Он выбирает
   источник данных:

   | Подпись | Загрузчик | Что показывает |
   |---|---|---|
   | **File** | `LoadListPersonsExtForFile` | персоны с лицами в этой серии (`personRepo.findByFileId`) |
   | **All** | `LoadListPersonsExtForProject` | все персоны проекта (`personRepo.findByProjectId`) |

2. **`LoadListPersonsExtForProject`** переведён с ленивой коллекции сущности
   (`projectExt.project.persons`) на запрос репозитория — так же, как оба
   соседних загрузчика: список наполняется в отдельном потоке, и обращение к
   ленивому полю вне сессии зависит от `enable_lazy_load_no_trans`. Убран
   `println(personExt)` на каждого персона — список теперь наполняется по
   кнопке, 53 строки в журнал за нажатие не нужны.

3. **`restorePersonSelectionAfterPersonsReload`** — после смены источника
   элементы списка пересоздаются, выделение снимается, а `currentPersonExt`
   остаётся от прежнего человека. Новая функция возвращает персону в
   выделение, если она в новом списке есть; иначе очищает выделение, список
   лиц и панель лиц. Иначе панель продолжала бы показывать человека, которого
   в списке уже нет. Вызывается из обоих слушателей загрузки
   (`isDoneLoadListPersonsExtForFile`, `isDoneLoadListPersonsExtForProject`).

4. **Документация**: в `docs/domains/faces/domain.md` добавлен раздел
   «Список персон в редакторе планов» с двумя источниками и тремя инвариантами.
   В `AGENTS.md` запись долга переписана, версия **2.5.0 → 2.6.0**, добавлены
   записи в Changelog (включая пропущенную 2.5.0).

## Ничего не потеряно

До вчерашней правки список был один и **проектный** — это сделано было
намеренно (комментарий в `LoadListPersonsExtForFile`: персонаж, отмеченный в
первой серии, должен быть в списке и во второй). Теперь это поведение
доступно по кнопке **All**. Переключатель, нарисованный и никогда не
работавший, наконец получил смысл.

Значение по умолчанию не менялось: `rbPersonFile selected="true"` в FXML, то
есть при открытии окна список — персоны серии.

## Что осталось

- `doSelectFacesRb` (переключатель лиц) по-прежнему только пишет в журнал:
  в контроллере один набор лиц `listFacesExt`, разделять наборы — отдельная
  задача.
- Известный долг рядом: `doSelectFacesCb` разыменовывает `currentPersonExt!!`,
  то есть щелчок по любому из четырёх флажков **до выбора персоны** уронит
  поток загрузки. Не трогал — это отдельная правка.
- Правая панель планов склеивает соседние строки (долг с прошлых дней).
