# Отчёт: завершать JVM при закрытии главного окна

Задача #230. Снимает долг из `docs/adr/0005-sequential-threads-no-pool.md`.

## Причина

Две независимые причины, почему закрытие окна не завершало процесс:

1. **Инструмент JavaFX не получал команду выйти.** Главное окно создаёт не
   `Application.launch`, а `ProjectEditFXController` (`Stage()` и `showAndWait()`
   вручную), поэтому параметр `stage` метода `start` игнорируется, а
   `Platform.exit()` не вызывался никем.

2. **Рабочие потоки — не-демоны.** `LoadList*`, `UpdateList*` и `RunListThreads`
   создаются как обычные `Thread()`. В `RunListThreads` и в
   `ProjectEditFXController` стоит явное `isDaemon = false`. Пока такой поток
   жив, JVM не завершается, даже если инструмент JavaFX уже остановлен.

## Решение

`ProjectFXApp.start()`:

- после возврата из `editProject` вызывается `Platform.exit()`;
- регистрируется shutdown-хук, который находит живые не-демонные потоки с
  именами `RunListThreads`, `LoadList*`, `UpdateList*` и прерывает их.

**Почему прерывание, а не `isDaemon = true`**: обработка пишет файлы и строки
в базу. Обрыв на середине оставил бы недописанный артефакт или полузапись.
Прерывание даёт потоку шанс завершиться штатно.

## Что проверено и как

Полный цикл на живой машине: запуск → закрытие окна → проверка.

| Проверка | Результат |
|---|---|
| `mvn -q clean compile` | код 0 |
| Первый запуск, окно появилось | 12 с |
| Закрытие окна, время до конца процесса | **2 с**, процесс умер |
| Процессы ivfx после закрытия | нет |
| `h2db.mv.db` после закрытия | свободна |
| Второй запуск без перезапуска машины | **стартовал**, БД не заблокирована |
| Второй цикл закрытия | **2 с**, процесс умер |
| Исключения в логе | нет |

Для сравнения, до правки: 24,2 ГБ и 17,9 ГБ удержанной памяти, завершение
только по SIGTERM вручную.

## Что осталось

Shutdown-хук прерывает потоки, но не убивает дочерние процессы ffmpeg:
`projectactions` не проверяют `isInterrupted` и не завершают свой
`ProcessBuilder` (ADR-0005). Если закрыть окно во время длинной операции,
ffmpeg продолжит работать как сирота. Это отдельный долг, в этой задаче
не решается — требует правки самих операций.
