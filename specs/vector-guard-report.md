# Вектор лица обнулялся результатом распознавания

## Что случилось

На восьмой серии редактор показывал пустую панель лиц, треков не было, а
трекирование падало:

```
java.lang.NumberFormatException: empty String
  at com.svoemesto.ivfx.modelsext.FaceExt.getVector(FaceExt.kt:117)
  at com.svoemesto.ivfx.modelsext.FaceExt.<init>(FaceExt.kt:126)
```

В базе у **7 597 лиц из E08** был пустой вектор — ровно столько же, сколько
распознала машина. Совпадение числа и объяснило всё.

## Причина

В тот же день галерея и очередь были разведены по файлам, и из входного json
**убрали векторы**: вместо 583 МБ текста скрипт получил матрицу. Так и было
задумано.

Но скрипт возвращает **те же записи, которые получил**. Значит в
`recognize_faces_result.json` к каждому распознанному лицу пришёл
`"vector": []`. Применение сравнило его с имеющимся, различие нашлось — и
записало пустую строку вместо эмбеддинга.

Дальше пустая строка падала при чтении: `FaceExt` разбирает её как массив из
одного пустого элемента, а `Double.parseDouble("")` не существует.

## Что сделано

Защита на двух уровнях, потому что винова вся цепочка:

1. **Запись вектора отказывается от пустого массива.** Пустой вектор означает
   «данных нет», а не «стереть имеющееся».
2. **Применение не трогает вектор, если в json пусто.** Там, где приходят
   данные.
3. **Чтение пустого вектора больше не падает**, а возвращает пустой массив:
   редактор не должен валиться из-за значения в базе.

## Восстановление

Вектора взяты из `faces.json` — выхода детектора по E08, где они целы.
Одна операция `UPDATE tbl_faces ... FROM` по ключу «номер кадра + номер лица»,
15 095 строк. Проверено после: **пустых векторов ноль во всех восьми сериях**,
размеченные лица на месте, треки целы.

## Урок

Проверялась эквивалентность **скрипта**: тот же результат на тех же данных.
А сломался **путь возврата** — то, что происходит между «скрипт посчитал
правильно» и «данные уехали в базу». Между этими точками есть ещё
применение, и оно молча ломало данные.

**Правило**: данные, которых нет во входе, не должны интерпретироваться как
команда удалить их. Проверять надо оба конца пути, а не только тот, который
считает.
