# Карта «Ускорение распознавания лиц» — итог

## С чего было

Прогон распознавания на пятой серии: **65,8 секунды**, из которых применение
результата — 21,5, то есть треть времени, при том что один поиск лица в базе
занимает 2,3 мс. Вопрос был не «где тормозит», а «где не идёт работа».

## Что оказалось

| причина | где |
|---|---|
| транзакция на каждое лицо | `enable_lazy_load_no_trans` открывает новую сессию на каждое ленивое чтение |
| 700 запросов на сбор галереи | обход «серия × персона» вместо одного запроса |
| скрипт переписывает 492 МБ json | чтение и запись файла, 69 % которого — галерея, которая только читается |
| умножение матрицы на вектор на каждое лицо | матрица галереи перечитывалась 1,03 ТБ за прогон |
| два обращения к базе на лицо | поиск и сохранение по одному |

## Что стало

Прогон на седьмой серии: **52,4 секунды**.

| | было | стало |
|---|---:|---:|
| применение распознавания | 54 мс на лицо | **1,5 мс** |
| применение создания лиц | 173,6 с | **8,2 с** |
| скрипт | 65,8 с | 18,3 с |
| галерея на приложение | 37 614 | 53 291 |

## Решения владельца, принятые по ходу

- **Галерею не урезаем** (#252, закрыт решением): полнота важнее времени.
  По замеру урезание до 20 лиц на персону стоит около 5 процентных пунктов
  полноты.
- **Порог распознавания не двигаем** без замера: распознание считается
  хорошим.
- **Границы серий — свойства, а не поля**; считаются по команде оператора.

## Что осталось

Сбор галереи — **18 секунд из 52**, 34 % прогона. Вынесено в #265.
